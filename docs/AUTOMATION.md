# الأتمتة في THE VAULT — دليل مختصر

> ملف مرجعي بالعربية للمالك. التوثيق التقني الكامل بالإنجليزية في `CLAUDE.md`.

هذا الملف يشرح **الأشياء اللي تشتغل لحالها** في المشروع: متى تشتغل، وليش، وكيف توقفها.

---

## ١. سكربتات Git التلقائية

Git يقدر يشغّل سكربتًا **من نفسه** عند لحظات معيّنة. المصطلح الإنجليزي لها **git hooks**.
عندك ثلاثة، كلها في مجلد `.githooks/`:

| السكربت | متى يشتغل | وش يسوي |
|---|---|---|
| `pre-commit` | **قبل** تسجيل الـcommit | يرفض الـcommit لو عدّلت كودًا يُنشر بدون ما ترفع رقم النسخة، ثم يفحص **العقود** بين الملفات (القسم التالي) |
| `post-commit` | **بعد** كل commit | يعيد بناء خريطة المعرفة (القراف) في الخلفية |
| `post-checkout` | عند `git checkout` | يزامن القراف مع الفرع الجديد |

مربوطة عبر الإعداد:
```bash
git config core.hooksPath .githooks
```

### حارس النشر (`pre-commit`) — الأهم

**المشكلة اللي يحلّها**: النسخة مكتوبة في **كل المواضع** عبر ٨ ملفات (`index.html` ×١٤، و`js/app.js`، و`version.json`، و`manifest.json`، و`admin.html`، و`privacy.html`، و`get/index.html`، و`CLAUDE.md`). لو عدّلت كودًا ونسيت ترفعها، الأجهزة تظل على النسخة القديمة من الكاش — **الإصلاح ما يوصل ولا جهاز**، وما فيه أي رسالة خطأ تخبرك.

صار عندك فعلًا في الـcommit رقم `ea6c74e`.

فالحارس يوقفك:
```
✖ check-release: this commit ships code but does NOT bump the version.
    Fix:  npm run release  &&  git add -A
```

**لتجاوزه** (لو التعديل توثيق فقط ومو كودًا يُنشر):
```bash
SKIP_RELEASE_CHECK=1 git commit -m "..."
```

### فاحص العقود (`check-contracts`) — يشتغل في نفس الـpre-commit

```bash
npm run check            # يفحص ٢٨ عقدًا بين الملفات، بدون تعديل
```

**المشكلة اللي يحلّها**: التطبيق سبعة ملفات JS تشترك في نطاق واحد، وقاعدة بيانات، وعامل Cloudflare، ولوحة تحكّم — وكثير من الأشياء فيه «لازم تطابق» شيئًا في ملف آخر، وما كان يحرسها إلا تعليق. الفاحص يقرأ الملفات ويقارن الطرفين ويطبع بالضبط وش اللي اختلف. أمثلة على ما يفحصه:

- ترتيب تحميل السكربتات = ترتيب الاعتماد بينها.
- كل مفتاح ترجمة موجود بالعربي **و**بالإنجليزي.
- كل جدول أو دالة أو حاوية يناديها التطبيق موجودة فعلًا بعد تشغيل ملفات `backend/migrations` بالترتيب، وأسماء وسائط كل `rpc()` تطابق تعريفها في SQL.
- مفاتيح `localStorage` كلها من السجل الواحد في `js/cloud.js`، ما فيه نسخة مكتوبة بالحرف في مكان ثاني.
- كل رسالة خطأ يرجّعها العامل لها ترجمة في التطبيق.
- أرقام الـAPK في `version.json` = أرقام `build.gradle`، و`js/health.js` ما ينادي إلا دوال معلنة في الإضافة الأصلية (Kotlin).
- **لوحة التحكّم تحسب نفس أسبوع التطبيق** (يبدأ الأحد): دالة `admin_user_stats()` في SQL، وحسابا الأسبوع في `admin.html`، وكل عبارة «الأسبوع من …» — كانت اللوحة تحسب من السبت والتطبيق من الأحد، فيطلع للمستخدم نفسه رقمان للالتزام في نفس الصباح.
- العناصر الثابتة في `index.html` اللي يبحث عنها الكود بالاسم (شريط التنقل، جذر النوافذ، التوست…) موجودة فعلًا — تغيير اسم واحد منها كان يبيّض الشاشة كلها.
- جدول الأخطاء `client_errors` يقبل كل نوع خطأ يرسله التطبيق — نوعان كانا يُرفضان بصمت، فسجلّ الأخطاء في اللوحة ما كان يستقبلهما.
- الأيقونات: كل اسم أيقونة في الكود موجود في مجموعة `ICONS` (الاسم الغلط يرسم فراغًا بلا خطأ)، والنسخ السبع المكرّرة خارجها مطابقة للأصل.
- العامل (Worker): أطول تعليمات يرسلها التطبيق (الصورة، الصوت، دفعة الوصفة) تدخل ضمن حدوده، وقائمة الأصول المسموحة تشمل كل منفذ يشتغل عليه خادم التطوير.
- أي دالة في قاعدة البيانات سُحبت صلاحية تنفيذها من الزوّار تبقى مسحوبة: حذف الدالة وإعادة إنشائها يعيد الصلاحية تلقائيًا (صار فعلًا في الترحيل ١٩، وأصلحه ٢٣).

**ما فيه تجاوز له.** لو كسر عقدًا، أصلح الطرف الغلط — ولو المراجعة لقت تعليق «لازم يطابق» جديد، أضف عقدًا في `scripts/check-contracts.js` بدل ما تصلح الحالة بيدك.

## ٢. أمر الإصدار

```bash
npm run release          # يرفع النسخة في كل المواضع ثم يتحقق منها
npm run release:check    # يفحص فقط، بدون تعديل
```

بعده: `git add -A` ثم commit ثم push. GitHub Pages ينشر خلال دقيقة تقريبًا.

**لا ترفع الأرقام يدويًا.** السكربت يعيد قراءة الملفات من القرص بعد الكتابة ويفشل لو اختلف موضع واحد.

### التراجع عن إصدار سيئ
كل الأجهزة تحمّل نفس الرابط الحيّ، فالإصدار السيئ يوصل الجميع دفعة واحدة.

```bash
git revert <رقم-الcommit-السيئ>
npm run release          # للأمام دائمًا
git add -A && git commit && git push
```

⚠️ **لا ترجع بالرقم للخلف.** المحدِّث يقارن الأرقام، والأجهزة **لا تنزل** لنسخة أقدم — بتعلق على السيئة.

## ٣. خريطة المعرفة (القراف)

تتحدث تلقائيًا بعد كل commit. مخرجاتها في `graphify-out/`:

| الملف | وش هو |
|---|---|
| `graph.html` | القراف التفاعلي — **افتحه بالمتصفح** |
| `graph.svg` | صورة للّصق في README |
| `GRAPH_REPORT.md` | تقرير مكتوب |
| `wiki/` | مقال لكل مجتمع |

**تكلفة التحديث التلقائي: صفر** — الكود يُقرأ ببنية الشجرة (AST) بلا ذكاء اصطناعي.

- `.graphifyignore` يستبعد المكتبات الخارجية والصور، عشان القراف يوصف **مشروعك** لا مكتبات غيرك.
- `scripts/graph-crossfile.js` يضيف الروابط بين الملفات، لأن التطبيق **ما فيه أي `import`** — الملفات تتواصل عبر متغيّرات عامة (`window.DB`)، وقارئ الشجرة لا يراها.
- تعديل **الوثائق** يحتاج تمريرة يدوية (تحتاج ذكاءً اصطناعيًا) — التلقائي يغطي الكود فقط.

## ٤. أشياء **لا** تتحدث تلقائيًا

| الشيء | متى يلزم | كيف |
|---|---|---|
| **Cloudflare Worker** | عند تعديل `backend/worker/gemini-worker.js` | لصق يدوي في لوحة Cloudflare ثم Deploy |
| **قاعدة البيانات** | عند تعديل أي `backend/*.sql` | تشغيل يدوي: لصق في محرر Supabase، أو عبر أداة Supabase MCP إن كانت متاحة في الجلسة. وفي الحالتين يُسجَّل المسار والتاريخ في جدول `backend/README.md` |
| **إعدادات الحسابات** | مرة واحدة، بيدك | في لوحة Supabase ← Authentication: أقل طول لكلمة السر ٨، وحماية الكلمات المسرّبة، وقرار التسجيل المفتوح (إمّا إغلاقه والدعوة يدوياً، أو تأكيد البريد مع كابتشا). لا يمكن ضبط أي منها من الكود. |
| **APK جديد** | **فقط** عند تعديل أصلي (إذن، إضافة Capacitor، كود جافا/كوتلن) | راجع `docs/ANDROID.md` |

### مهم عن الـAPK
التطبيق **قشرة تحمّل الرابط الحيّ**. يعني تعديلات الويب (JS/CSS/HTML) **توصل للمستخدمين تلقائيًا** عند فتح التطبيق، **بدون إعادة تثبيت**.

فلا تبني APK جديدًا لتعديل ويب — ما راح يغيّر شيئًا للمستخدم، وبيطلب منه إعادة تثبيت بلا فائدة.

## ٥. إيقاف كل شي

```bash
git config --unset core.hooksPath
```
يوقف السكربتات الثلاثة. لإعادتها: `npm run hooks`.
